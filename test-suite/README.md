# Cash Flow Intelligence — LLM vs SLM Testing Suite

Testing suite for evaluating the Performance, Parsing Accuracy, and Advice Quality of the Cash Flow Intelligence chatbot. It compares LLMs (Gemini) against SLMs (Gemma).

---

## Prerequisites

All configurations and API keys are read from the `.env` or `.env.local` files in the root directory. Ensure that `VITE_GEMINI_API_KEY` (or `GEMINI_API_KEY`) is configured correctly.

We run scripts using `npx tsx` instead of `ts-node` due to modern Node.js v22+ ES module compatibility.

---

## 1. Latency & DB Overhead Testing

This module evaluates the model's inference latency, parsing overhead, and database write latency.

### Command
> Note: run directly with `npx tsx` — `npm run ... -- --flag` is unreliable because npm mangles custom flags like `--engine`.

```bash
npx tsx test-suite/latency/run-latency.ts --engine=<llm|slm> --n=<repetitions> [--no-db]
```

### Options
*   `--engine` (Required): Specify either `llm` (runs Gemini models) or `slm` (runs Gemma models).
*   `--n` (Default: `30`): Number of repetitions per prompt.
*   `--no-db` (Optional): If passed, database writes to Firestore are bypassed.

### How to Modify Prompts
Prompts are loaded from `test-suite/latency/prompts.txt`. You can edit this file to add, modify, or delete the test prompts (one prompt per line). If the file does not exist, a default set of 15 noisy Indonesian prompts will be generated.

### Outputs
*   Raw results: `test-suite/results/latency_raw_<engine>_<timestamp>.json`
*   Summary CSV: `test-suite/results/latency_summary_<engine>_<timestamp>.csv`

## 2. Parsing Accuracy Testing

This module evaluates how accurately the models extract financial intent, amount, category, and date.

### Command
```bash
npx tsx test-suite/accuracy/run-accuracy.ts --engine=<llm|slm> --dataset=<path_to_csv>
```

### Options
*   `--engine` (Required): Specify `llm` or `slm`.
*   `--dataset` (Required): Path to the ground truth CSV dataset (e.g. `test-suite/accuracy/sample-dataset.csv`).

### Dataset Specifications
The CSV dataset must have exactly 5 columns with a header matching:
`Prompt,True_Type,True_Amount,True_Category,True_Date`

*   `True_Type`: Either `EXPENSE` or `INCOME`.
*   `True_Amount`: Purely numeric amount (no punctuation/k/million symbols, e.g., `25000` rather than `25k`).
*   `True_Category`: Must match one of the active categories (e.g., `Food & Beverage`, `Transportation`, `Bill`, `Salary`, `Bonus`).
*   `True_Date`: Format `YYYY-MM-DD`.

### Outputs
*   Predictions detail: `test-suite/results/accuracy_predictions_<engine>_<timestamp>.csv`
*   Performance metrics: `test-suite/results/accuracy_summary_<engine>_<timestamp>.json`

## 3. Financial Advice Relevance Testing (LLM-as-a-Judge)

This module evaluates the budget advice and financial summaries generated by the models using a separate judge model in a blind test.

### Command
```bash
npx tsx test-suite/relevance/run-relevance.ts --engine=<llm|slm> [--rounds=<number>]
```

### Options
*   `--engine` (Required): Specify `llm` or `slm`.
*   `--rounds` (Default: `3`): Number of evaluation rounds for the judge model per transaction history.

### Configuring the Judge Model
By default, the judge model uses `gemini-3.5-flash` to evaluate the outputs. You can change the judge model by setting `JUDGE_MODEL` in your `.env.local` or `.env` file:
```env
JUDGE_MODEL=gemini-1.5-pro
```

### How to Modify History Data
Transaction histories are loaded from `test-suite/relevance/sample-history.json`. You can edit this file to mock different monthly financial data patterns for the model.

### Outputs
*   Raw judge evaluations: `test-suite/results/relevance_raw_<engine>_<timestamp>.json`
*   Relevance summary: `test-suite/results/relevance_summary_<engine>_<timestamp>.csv`

## 4. Evaluation Summary Generator

Once you have run all modules for both the `llm` and `slm` engines, you can generate a consolidated markdown comparison table.

### Command
```bash
npx tsx test-suite/summarize.ts
```

### Outputs
Generates a markdown table matching the paper structure in `test-suite/results/evaluation_summary.md`, comparing LLM vs SLM across:
*   Model Inference Latency (Mean & P95)
*   Macro-F1
*   Exact-Match Accuracy
*   Average Contextual Accuracy, Relevance, and Actionability
